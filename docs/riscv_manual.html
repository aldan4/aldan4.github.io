RISC-V manual

The instruction set cheatsheet

ortfero

The RISC-V instruction set as the aldan machine runs it: RV64 with M, F, D, Zicsr, Zifencei, Zba, Zbb, Zbs, Sdtrig and a subset of V, in machine mode. Each instruction is listed with what it does; whatever aldan leaves out is marked. Opcodes, CSR numbers and codes are hexadecimal; bit positions, counts and sizes are decimal. The devices and the memory map are in the aldan codex.

A single held in a 64-bit register is NaN-boxed: the upper 32 bits are all ones. A single that is not boxed reads as the canonical NaN.

Vector registers

32 registers v0 to v31 of VLEN = 256 bits on aldan, and the CSRs vl, vtype, vstart, vxrm and vxsat. v0 holds the mask of a masked instruction. All of them are caller-saved.

Memory

  • One byte-addressed space of 2^64 bytes, little-endian.
  • Only loads and stores touch memory; every other instruction works on registers.
  • An instruction is 32 bits and 4-aligned: without C, a jump or branch to a pc that is not 4-aligned traps (cause 0). Data may be misaligned, at the cost of a trap on some machines; aldan never traps on either.
  • The model is RVWMO: another hart or a device may see stores in another order until a fence. Aldan has one hart and devices that finish inside the store, so a fence is never needed there.

Instruction formats

Every instruction is one 32-bit word. The opcode is bits 6-0, rd 11-7, funct3 14-12, rs1 19-15 and rs2 24-20, in every format that has them.

       31-25     24-20   19-15  14-12    11-7     6-0
R  |   funct7  |  rs2  |  rs1  |  f3 |    rd   | opcode |
I  |      imm 11:0     |  rs1  |  f3 |    rd   | opcode |
S  |  imm 11:5 |  rs2  |  rs1  |  f3 | imm 4:0 | opcode |
B  |  12,10:5  |  rs2  |  rs1  |  f3 |  4:1,11 | opcode |
U  |            imm 31:12            |    rd   | opcode |
J  |       imm 20,10:1,11,19:12      |    rd   | opcode |
R4 |  rs3,fmt  |  rs2  |  rs1  |  rm |    rd   | opcode |
V  |   f6,vm   |  vs2  |  vs1  |  f3 |    vd   |   57   |
  • Every immediate is sign-extended from its top bit, which is always bit 31 of the word.
  • I and S hold 12 bits: -2048 to 2047.
  • B and J encode even offsets: a branch reaches 4 KB each way, jal 1 MB.
  • U is the upper 20 bits of a 32-bit value: lui sets it, addi adds the low 12, and a negative low part needs the upper part one higher.

Taking a trap

  • Entry: mepc = pc, mcause and mtval set, MPIE = MIE, MIE = 0, MPP = the old mode, pc = mtvec base. In vectored mode an interrupt goes to base + 4 * code.
  • mepc points at the instruction itself: an ecall or ebreak handler adds 4 before mret.
  • mret: MIE = MPIE, MPIE = 1, pc = mepc.
  • An interrupt is taken when its mip and mie bits are both set and mstatus.MIE is on. External beats software, which beats timer.
  • wfi waits until some interrupt is pending and enabled in mie, whatever mstatus.MIE says; with MIE off it just falls through to the next instruction.

Timer and software interrupts

MTIP is high while mtime >= mtimecmp, two 64-bit registers of the clint; writing a later mtimecmp clears it. MSIP is bit 0 of the clint's msip register. The time CSR reads mtime.

Debug triggers (Sdtrig)

tselect (7A0) picks a trigger; tdata1 (7A1) sets it up, its type in bits 63-60; tdata2 (7A2) holds its address; tinfo (7A4) lists the types it can take. Aldan has 8 triggers of type 6, mcontrol6 (execute at an exact address), and 3, icount (step a count of instructions). A trigger that fires is a breakpoint: mcause 3. tcontrol (7A5) holds the bit that keeps triggers off inside a handler.

The PLIC

The platform-level interrupt controller gathers the lines of the devices and offers them to the harts as one external interrupt, MEIP.

  • Each source 1 to 1023 has a gateway, a pending bit and a priority; 0 is no source. Priority 0 never interrupts, and the higher priority wins, then the lower id.
  • A context is a hart in one mode; it has an enable bit per source and a threshold. A source interrupts the context when it is pending and enabled, and its priority is above the threshold.
  • Claim: a read of the context's claim register returns the best source and clears its pending bit, or returns 0 when there is none.
  • Complete: writing that id back to the same register. The gateway sends no new request for the source until then; a level-triggered line that is still high is pending again at once.
  • So a handler claims, serves the device until its line drops, then completes, and claims again until 0.

V: vectors

The model

  • Each of the 32 registers holds VLEN bits: 256 on aldan, so vlenb = 32 bytes.
  • vtype sets the element width SEW and the group LMUL: a group of LMUL registers acts as one longer register, and an operand names its first, a multiple of LMUL.
  • vl is the number of elements an instruction works on, at most VLMAX = LMUL * VLEN / SEW. The ones past vl are the tail.
  • A masked instruction, written with a last operand v0.t, works only on the elements whose bit is set in v0: bit i of v0 for element i.
  • vta and vma pick what tail and masked-off elements become: undisturbed, or agnostic (anything, perhaps all ones). Aldan always leaves them undisturbed.
  • vstart is the element to resume from after a trap; it is 0 otherwise.

A loop

The count left goes into vsetvli at each pass, and the pass takes as many elements as fit; there is no remainder loop. This adds 1 to a0 words from a1 into a2:

loop:
    vsetvli t0, a0, e32, m8, ta, ma
    vle32.v v8, (a1)
    vadd.vi v8, v8, 1
    vse32.v v8, (a2)
    sub     a0, a0, t0
    sh2add  a1, t0, a1
    sh2add  a2, t0, a2
    bnez    a0, loop

Operands

An instruction is named for its operands: .vv two vectors, .vx a vector and an integer register, .vi a vector and a 5-bit immediate, .vf a vector and a float register, .vs a vector and element 0 of another, .mm two masks, .vvm and the rest a mask in v0 as well. The second source comes first: vsub.vv vd, vs2, vs1 is vd = vs2 - vs1. The immediate is signed, but unsigned for shifts and slides.
