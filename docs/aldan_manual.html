Aldan manual

The hardware cheatsheet

ortfero

The machine as a program sees it: the processor, the memory map, and the registers of every device. It is enough to bring the machine up and to drive each device from nothing. Addresses, offsets, ids, codes and register values are hexadecimal; counts, sizes and dimensions are decimal, but for the sizes in the memory map.

The machine

  • One hart, RV64 with M, F, D, V, Zicsr, Zifencei, Zba, Zbb, Zbs and Sdtrig. Every instruction is 32 bits: there is no C extension. The instructions are listed in the riscv codex.
  • No A extension: there is no LR/SC and no AMO. With one hart, masking interrupts is the only lock.
  • Machine mode only. There is no S or U mode, no paging and no PMP: one address space, all of it reachable.
  • 16 MB of RAM at 80000000, the first 128 KB of it the boot ROM. Little-endian.
  • The devices: a timer (clint), an interrupt controller (plic), a serial line, a real-time clock, a power switch, five virtio transports (host directory, network, keyboard, sound, display) and an NVMe disk on a PCI bus.
  • Every device does its work inside the store that asks for it: a virtio notify or an NVMe doorbell has finished when the store returns. Only what comes from outside — a key, a frame, the sound being played — arrives later.

The processor

Instructions

  • I, M, F, D in full. F and D are always on: mstatus.FS is not modelled.
  • Zba, Zbb and Zbs in full.
  • fence and fence.i do nothing and are not needed: code written by a store or by DMA runs as written.
  • V is a subset of RVV 1.0, with VLEN 256 (vlenb 32) and ELEN 64.

Any other CSR number is accepted without a trap and lands in a 128-entry array indexed by its low seven bits, so unrelated CSRs alias each other: cycle (C00) reads mstatus, and a write to satp (180), sstatus (100) or mcycle (B00) overwrites mstatus. Keep to the table.

Traps

  • Entry: mepc = pc, mcause, mtval, MPIE = MIE, MIE = 0, pc = mtvec. mret: MIE = MPIE, pc = mepc, then any pending enabled interrupt is taken at once.
  • The causes raised are 2 (illegal instruction, mtval the word), 3 (ebreak or a trigger, mtval the pc) and B (ecall). Misaligned and unmapped accesses never trap.
  • The interrupts are 8000000000000003 (software), ...07 (timer) and ...0B (external), taken in the order external, software, timer.
  • Interrupts are sampled only at certain points: every 8192 instructions, at wfi, at mret, and on a write to mstatus or mie. Expect up to 8192 instructions of latency.
  • wfi stalls the hart until mip and mie have a bit in common, whether or not mstatus.MIE is set, and the host idles while it waits.

Reset

  • pc = 80000000, the start of the ROM. a0 = 0, the hart id; a1 = 80800000, the device tree. Every other register and CSR is 0: interrupts are off and mtvec is 0.
  • RAM is not cleared, and a reboot does not reset the devices: the plic, the clint, the serial line and the clock keep their state. Set each up from scratch.

  • The ROM holds the firmware, placed there by the host before power-on. It is not write-protected: the CPU can store into it, but no device can reach it.

Access rules

  • Any alignment works, and nothing traps.
  • An address that is neither RAM nor a device is taken as 80000000: a stray or null pointer silently writes over the reset vector.
  • Device registers decode exact offsets. A read of any other offset gives 0, and a write is dropped.
  • A device sees no access width: a load is cut to its size after the read, and a store's value is cut by the device. Use the width each register names.
  • lh and lhu are done as two byte reads, so never use them on a device.

Timer

The clint at 02000000 counts wall-clock time at 10 MHz.

  • mip.MTIP is high while mtime >= mtimecmp. Write a later mtimecmp to clear it, or all ones to disarm it.
  • Use sd and ld. A sw to 4000 or BFF8 sets the whole register to the zero-extended word.

Clock

A goldfish real-time clock at 00101000: nanoseconds since 1970, from the host's wall clock.

OffsetRegister
0TIME_LOW, 32 bits. Read it first: it latches the high half. A write sets the time
4TIME_HIGH. Read it second; write it first

The clock has no alarm and no interrupt.

Power

One register at 00100000, written with sh: 5555 powers the machine off, 7777 reboots it. The host acts at the end of the current slice, so follow the store with a wfi loop.

Serial line

A 16550 subset at 10000000, byte registers one apart. It needs no set-up: the baud rate is ignored, and a byte written is out at once.

OffsetRegister
0Read: RBR, the next byte in. Write: THR, a byte out
1IER: bit 0 raises source A while a byte waits
2IIR: 4 while a byte waits, else 1
5LSR: 60 always (THR empty), and bit 0 while a byte waits

LCR, MCR, FCR and SCR are stored and do nothing. Read RBR until LSR bit 0 clears to drop the line.

  • Bring-up: status 0, then 1 (acknowledge), 2 (driver); write the features; 8 (features ok) and read it back; set up each queue; 4 (driver ok).
  • The device offers its own bits and VERSION_1 (bit 32, select 1), which the driver must take. No indirect descriptors, no event index.
  • Queues are split rings. The descriptor table is 16-aligned, the available ring 2-aligned, the used ring 4-aligned, all in DMA memory. Write the low address half before the high one.
  • Descriptor: le64 address, le32 length, le16 flags (1 next, 2 device-writable), le16 next. A chain lists what the device reads first, then what it writes.
  • A bad chain or queue sets status bit 40 (needs reset), and the device stops until status is written 0.
  • The line is high while the interrupt status is not 0. Polling the used ring works as well.

Keyboard

  • Event: le16 type, le16 code, le32 value, one to each buffer posted on queue 0. A key gives type 1 (EV_KEY) with value 1 down, 0 up, 2 repeat, then type 0 (sync).
  • The codes are Linux evdev positions for a US board: 1 esc, 2-B digits, 1C enter, 1D left ctrl, 2A left shift, 38 left alt, 39 space, 3B-44 F1-F10, 57-58 F11-F12, 61 right ctrl, 64 right alt, 66-6F home, up, page up, left, right, end, down, page down, insert, delete. Characters and modifiers are the driver's.
  • Queue 1 buffers come straight back.

Display

virtio-gpu, 2D only. The screen is 780 x 520 times a scale of 1 or 2, or 0 x 0 with no window. Pixels are 32-bit B8G8R8X8, a little-endian xrgb word.

Every request starts with a 24-byte header: le32 type, le32 flags, le64 fence, le32 context, u8 ring, padding. The reply is a header of its own, 1100 when all is well.

Sound

virtio-sound with one output stream, id 0: signed 16-bit mono at 48 kHz, nothing else. Control requests go on queue 0 and start with le32 code, replies with le32 status: 8000 ok, 8001 bad message, 8002 not supported, 8003 I/O error.

CodeRequest
101Set params: stream, buffer bytes, period bytes, features, then u8 channels 1, format 5, rate 7, pad
102Prepare: stream
104Start: stream
105Stop: stream
103Release: stream
100Info: start, count, size; one 32-byte record
  • Play by posting chains on queue 2: le32 stream 0 and the samples, then 8 writable bytes for le32 status and le32 latency. A buffer comes back when the host has played it, and that is the only clock the stream has.
  • Buffers are taken once the stream is prepared.

Network

virtio-net, feature MAC (bit 5) only. The configuration holds the MAC 52:54:00:12:34:56. Every frame has a 12-byte header in front of it, all zero but for a 1 at byte 10 on receive. Frames are Ethernet without the checksum, up to 1514 bytes.

The host answers as a small router:

  • The guest is 10.0.2.15, the host 10.0.2.2 (MAC 52:55:0A:00:02:02). Only ARP requests for 10.0.2.2 are answered.
  • UDP only, unfragmented. Datagrams to 10.0.2.2 reach the host's 127.0.0.1; to any address outside 10.0.2.x they go out to it through a host socket.
  • No TCP, ICMP, DHCP or DNS of its own.

Host directory

virtio-9p over the directory aldan in the host user's home. The configuration is le16 length then the tag "aldan". One request to a chain: the message, then room for the reply.

  • 9P2000.L only, msize 4096 to 65536. Version first.
  • Messages: version, attach, walk (16 names at most), lopen, lcreate, read, write, readdir, getattr, setattr (size only), mkdir, unlinkat, renameat, fsync, flush, clunk. Any other gets Rlerror EOPNOTSUPP.
  • A name is one component: no slash, not . or .. — nothing above the directory can be reached. Symlinks are listed but cannot be opened.
  • A write's size field counts its data descriptors too.

Disk

An NVMe controller at PCI 00:01.0, reached through ECAM at 30000000 + device * 8000, so its configuration is at 30008000. Device 0 is a host bridge; nothing else is on the bus.

OffsetRegister
0Id 00101B36
4Command: 2 memory, 4 bus master, 400 INTx off
8Class 010802
10, 14BAR0, 64-bit, 4000 bytes; nothing assigned at reset

Bring-up: write BAR0 = 40000000 and BAR1 = 0, set command to 6, then use the controller's registers at 40000000. Configuration stores are whole words.

OffsetRegister
0CAP: queues of up to 64 entries, doorbell stride 4, 4 KB pages
14CC: write 00460001 to enable
1CCSTS: bit 0 ready, bit 1 fatal
24AQA: admin completion size - 1 at 16, admin submission size - 1 at 0
28, 30ASQ, ACQ: 64-bit page addresses
1000Doorbells: admin submission tail, admin completion head, then the same for queue 1
  • Ready is set the moment CC is enabled.
  • Two queues only: admin 0 and one I/O pair 1, each 2 to 64 entries, page-aligned and contiguous. Submission entries are 64 bytes, completions 16.
  • Admin: 05 creates I/O completion queue 1, then 01 its submission queue. Both take PRP1 = the queue's page and CDW10 = (size - 1) << 16 | 1; CDW11 is 1 for the completion queue (3 with interrupts) and 10001 for the submission queue. The admin completion queue always interrupts. There is no Identify and no Set Features: every other admin command fails with status 1.
  • I/O on namespace 1, 512-byte blocks: 02 read, 01 write, 00 flush. CDW10-11 the first block, CDW12 the block count less one. The capacity is the image's size; keep it in your own superblock.
  • PRP1 is any 4-aligned address. Past one page PRP2 is the next page, past two a list of page addresses.
  • Completion: DW2 = submission head, DW3 = command id, the phase in bit 16 and the status above it. The phase starts at 1 and flips at every wrap.
  • The line, source 21, is high while a completion queue with interrupts on has entries the head has not passed.
