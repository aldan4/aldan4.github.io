Aldos manual

The machine on one page

ortfero

What the machine is made of, how it comes up, how loom lays out its windows, and the commands that operate it, which help prints at the prompt too. The keys are in the keys codex, the hardware in the aldan codex and the instruction set in the riscv codex.

Architecture

The machine is built in layers, lowest first.

LayerWhat it is
MachineA 64-bit RISC-V computer with 16 MB of memory: a screen, a keyboard, a disk, sound, a network and a host directory
FirmwareThe boot ROM. It owns every driver and publishes one call table
AlmacThe resident binary, and the only one: the language, its compiler and the emergency prompt
AldosThe task, memory, volume, file and service managers, written in almac
CoreThe library every program draws on
ProgramsThe applications, loom among them
  • There is no kernel image and no system call. A program reaches aldos by importing it, the way it reaches core.
  • A program is a module: a .alm text file, compiled the first time it is imported and kept until reset.
  • Everything runs in one address space. Nothing isolates one module from another.
  • Fibers are cooperative: one runs until it yields, waits on a device or returns. A service is a fiber that goes on after the call that started it.

Drive /a is the system as it was built, one pack archive on the disk. It is read-only: an update replaces it whole, and a write to it is refused. Keep your own files on /b.

A path that does not begin with a slash is relative to the working directory. A dot is the working directory, two dots its parent.

Boot

  • The firmware reads the device tree, publishes its call table, and brings up the screen, the disk, the host directory, the network, the keyboard and the sound.
  • It loads /a/almac.bin from the boot disk and jumps to it. A failure here is reported by the firmware.
  • Almac reads /a/rc.alm. Its imports bring up the core library and the aldos modules beneath it, and its definitions make the commands.
  • The last line of rc.alm starts loom, which takes the screen and does not return.

A fault in rc.alm is reported as a module, a line and a reason, and leaves the machine at the emergency prompt; loom typed there goes back to the environment.

  • reset gives every module up, reads rc.alm again and starts loom again, without the firmware. It is how a change to rc.alm or to a config takes.
  • reboot goes through the firmware again, as a power cycle would.
  • halt powers the machine off. Nothing is saved.

Loom

Loom is the environment, and the only prompt a working machine shows.

The windows

Every app is a window of its own, with a fiber of its own, so a slow one never holds up another. The display shows one window or two: two halves side by side when it is wide, one when it is narrow (a phone held upright).

  • The repl is the first window, and is always there.
  • A new window opens with the keys, and the window that had them stands beside it.
  • A window lasts as long as it holds something. Putting down what it holds puts the window down too, and the keys go back to the window it was opened from.
  • The title of the window with the keys is inverted.
  • Only the repl takes commands. Every key in another window is that window's own.

Of the picture, the drawing, the music, the journal and the debugger there is one window each: opening another thing in it brings that window up holding it. A codex opens in a reader with help 'name: keys, aldos, aldan, almac, snippets or markoff. The viewer shows any text file as written, a markoff document among them; the reader takes a markoff document and nothing else, and renders it: paragraphs flow to the reading column, tables are drawn with box pieces.

Commands

Whatever is typed at the prompt is almac. A command is a function, called by its name.

  • A call without arguments needs no parentheses.
  • A string is written with a leading quote, 'name, or in double quotes when it holds a space.
  • Arguments are separated by commas.
  • No command takes an option.
> cd '/a/codex
> cp 'aldos_keys.moff, '/b
> edit "/b/my notes"
